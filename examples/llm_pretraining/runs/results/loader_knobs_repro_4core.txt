How to read it: the packer is a single Python thread. Every extra I/O or transform thread that also needs the GIL
takes turns with it. When the raw/cooked queues are full, the packer is not waiting for data; a main-thread CPU
share below 1.0 is time spent waiting for the interpreter lock. Fewer threads = more of the lock for the packer.
More owned splits = a bigger per-block state snapshot on that same thread.
